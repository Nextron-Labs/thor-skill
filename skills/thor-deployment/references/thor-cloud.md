# THOR Cloud and THOR Cloud Lite

Hosted consoles that run THOR on endpoints without agents: you define a **campaign** (scan
options), each campaign has its own **launcher**, the launcher runs THOR on a system and
reports results back to the campaign.

| | THOR Cloud Lite | THOR Cloud |
|---|---|---|
| Cost | free sign-up, 30 scans per month | commercial (contact Nextron sales) |
| Console | https://thorcloud-lite.nextron-services.com | own instance (e.g. `thor-cloud.nextron-services.com`) |
| Scanner / rules | THOR Lite engine, open-source YARA and Sigma rules, YARA Forge, your own IOCs/YARA/Sigma | full THOR, Nextron signature set |
| Modules | full THOR module set (files, processes, registry, SHIM cache, Amcache, event logs, tasks, services, WMI, users) | full |
| Platforms | Windows, Linux, macOS | Windows, Linux, macOS |
| Use | your own organization's systems only | per contract |

## Workflow

1. Sign up / log in. Set account defaults: YARA Forge package, global IOCs, exclusions,
   false-positive filters.
2. Create a campaign: scan profile (*Full Scan* for an assessment, *Quick Scan* for a fast
   first look), speed/resource setting, optional schedule.
3. Get the launcher: one file per platform, a copy-paste one-liner, or a download page link to
   send to system owners.
4. Run the launcher with administrator/root rights on each system (manually, GPO, SCCM,
   Intune, Ansible, EDR, Velociraptor `Generic.Scanner.ThorCloud`).
5. Read results in the campaign: alerts, warnings and notices per host; export as needed.

## Deployment notes

- Endpoints need outbound HTTPS to the THOR Cloud service (the Velociraptor artifact lists
  `…/dl` download endpoints of the service). Proxies must allow it.
- Separate campaigns per wave, business unit or OS keep results apart and let you vary options.
- The launcher token identifies the campaign: treat it like a credential and don't publish
  one-liners in tickets or public chats; close the campaign when the sweep is done.
- Scheduling and load: start waves; the first minutes of a scan are the heaviest. The
  campaign's speed setting is the Cloud counterpart to `--soft` / `--cpu-limit`.
- Results leave your network to Nextron's service: confirm this is acceptable (data
  protection, customer networks). Cloud Lite and THOR Lite are for internal use; paid
  engagements and third-party networks need a commercial license.
- Moving from Cloud Lite to full THOR: your custom rules carry over; campaigns do not (THOR
  Cloud is a separate instance).

Exact launcher command lines and options are generated by the console for each campaign;
copy them from the *Launcher* view instead of reconstructing them.
